# MinecraftLCE-7thGen — сборка Xbox 360 (Release)

Версия из `Xbox_BuildVer.h`: **0.0.1.0**, build **232**.
Платформа: Xbox 360 (PowerPC), тулсет XDK 2010-01, Release.
Файл запуска: `default.xex` (39 079 936 байт).

## Состав папки

```
Xbox360-Build\
  default.xex     — сама игра (переименованный Minecraft.Client.xex)
  res\            — runtime-ресурсы (670 файлов, ~155 МБ): текстуры, шрифты, звук, TitleUpdate
  README_RU.md    — этот файл
```

Игра ищет ресурсы по путям `GAME:\res\...` и `GAME:\res\TitleUpdate\res\...`,
где `GAME:\` — папка, из которой запущен `default.xex`. Поэтому `default.xex`
и `res` **обязаны лежать рядом**, структуру `res` менять нельзя.

## Запуск в Xenia (проверка на PC)

1. Скопируйте папку целиком, например в `H:\Temp\mc360\`.
2. Запустите Xenia Canary:
   `xenia_canary.exe "H:\Temp\mc360\default.xex"`
   (или в GUI: File → Open → `default.xex`).
3. Нужен профиль: Xenia → **Profile** → создать/выбрать профиль.
   Без профиля игра открывает диалог «Sign in» и не пускает в меню.
   В конфиге Xenia можно прописать автоматический вход:
   ```toml
   [Profiles]
   logged_profile_slot_0_xuid = "E000909152148941"
   ```
4. Главное меню появляется примерно через **30–60 секунд** после старта
   (сначала идёт заставка с подсказками). Кнопка **Play Game** должна быть
   активной (подсвечена).

### Управление с клавиатуры (Xenia, `keyboard_mode = 2`)

В `xenia-canary.config.toml`:

```toml
[HID]
keyboard_mode = 2
keyboard_user_index = 0
```

Режим 2 (passthrough) требует подключённого геймпада, зато клавиатура
работает и в системных диалогах Xbox 360. В режиме 1 диалог
«Gamer profile not online» на клавиатуру не реагирует — его надо нажать
кнопкой **A** на геймпаде (выбрать «Continue playing offline»).

Привязки по умолчанию:

| Кнопка Xbox | Клавиша |
|---|---|
| A | `;` (точка с запятой) |
| B | `'` (апостроф) |
| X | `L` |
| Y | `P` |
| Start | `X` |
| Back | `Z` |
| D-pad | `W` / `A` / `S` / `D` |
| Левый стик | `W` / `A` / `S` / `D` с Shift |
| Правый стик | `I` / `J` / `K` / `L` / `0x26`… |
| LT / RT | `Q`,`I` / `E`,`O` |
| LB / RB | `1` / `3` |

Окно Xenia должно быть в фокусе, иначе ввод не доходит до игры.

## Перенос на консоль (RGH / JTAG)

Работает только на консоли с RGH/JTAG (сборка не подписана для розничной
прошивки и не является официальным TU-пакетом).

Вариант «папкой» (проще всего):

1. Скопируйте папку на HDD консоли, например:
   `Hdd1:\Games\MinecraftLCE7\Minecraft360\` (внутри `default.xex` + `res`).
2. Запустите `default.xex` через Aurora / Freestyle Dash / XeXMenu.

Вариант «в Content» (как обычная XBLA-игра):

1. `Hdd1:\Content\0000000000000000\584111F7\00007000\<имя папки>\`
   (внутри `default.xex` и `res`).
2. Запуск из официального дашборда или через Aurora.

Сохранения создаются в:
`Hdd1:\Content\<XUID профиля>\584111F7\00000001\`

## Что внутри (наши доработки M2)

- Бесконечные миры во всех трёх измерениях (границы мира убраны), дальность
  прогрузки чанков ограничена 12 чанками, без «дыр».
- LRU-кэш чанков с подсчётом ссылок вместо утечек памяти; выгрузка не более
  128 чанков за тик (нет провалов до 0 FPS при смене измерения).
- Энд: исправлен урон дракона, портал выхода 2×3, возврат в Верхний мир,
  внешние острова, флаг `dragonKilled` в `LevelData` — после убийства дракона
  спайки/кристаллы/подиум и новый дракон не респавнятся.
- Автосейв, автозапуск мира, ПКМ в креативе, убрана стена Нижнего мира.
- Оптимизирован рендер дракона (eyes-pass рисует только голову/челюсть).

## Известные риски

1. **Память под сейв (исправлено 28.10.2026).** Раньше `ConsoleSaveFileOriginal`
   резервировал 2 ГиБ виртуальной памяти с `MEM_LARGE_PAGES` — Xenia на этом
   падала при создании мира (`BaseHeap::Alloc page count too big for requested
   range` + `Access Violation: write at 0x100000000`). Теперь для Xbox-сборки
   резерв 256 МБ обычными страницами, с откатом на 64 МБ / 16 МБ, если большой
   резерв не удался; вместо `__debugbreak()` пишется сообщение в отладочный лог.
   Если мир всё равно не создаётся — пришлите `xenia.log`, там будут строки
   `ConsoleSaveFileOriginal: reserved ...` / `failed to commit ...`.
   **Проверено в Xenia 28.10.2026:** создание мира, игра на 60 fps, пауза,
   сохранение (сейв 3.8 → 7.8 МБ) и загрузка сохранённого мира после
   перезапуска — работают, падений нет.
2. **Ассеты TU.** В сборке лежат base/TU-ресурсы из исходников (не TU81).
   Контент TU81 (Aquatic и DLC) с этой сборкой не совместим — не подкладывайте
   `res` от TU81, будет рассинхрон текстур/моделей.
3. **Версия 0.0.1.0 (build 232)** — это базовая версия исходников, без поздних
   TU-фич. Мир, созданный в TU81, этой сборкой не откроется (другой формат сейва).
4. **Первый запуск в Xenia медленный** — компиляция шейдеров; далее быстрее.
5. Сборка не подписана: на розничной консоли не запустится, нужен RGH/JTAG.
6. Если предыдущая попытка создания мира оставила «битый» сейв в профиле,
   удалите папку `content\<XUID>\584111F7\00000001` и создайте мир заново.

## Если что-то пошло не так

Лог Xenia: `xenia.log` рядом с `xenia_canary.exe`.
Ищите строки с `Exception`, `ERROR`, `XamContent`, `ResolvePath`.

Пришлите последние ~200 строк лога и скриншот — по ним видно, на каком этапе
(меню, выбор мира, создание мира, генерация чанков) происходит сбой.
